## 왜 별도 phase 로 떼어내나

Phase 2 시각 검증 (PoC fixture 5개를 Toolditor 단독 주입) 결과:

- bitmap / svg / shape 은 원칙대로 materialize 됨
- **text 는 bounds 와 실제 glyph 너비가 어긋남** — 특히 fontSize / lineHeight 가 정확히 전달됐는데도 캔버스에서 wrap 되거나 여백이 남음
- 사용자가 해당 text 를 선택해 Toolditor 의 등록 폰트 (`701_400`) 로 교체하면 즉시 bounds 와 일치

### 근본 원인 (한 줄)

> **"브라우저는 layout 을 계산한다"** 원칙의 **"브라우저"** 가 extraction 단계(Playwright) 와 render 단계(Toolditor Canvas) 에서 **서로 다른 폰트를 쓴다.**

- Playwright 는 OS 시스템 폰트 ("sans-serif" → 환경 의존) 로 렌더 + bounds 측정
- Toolditor 는 등록된 웹폰트 (`701_400` 등) 로 렌더
- 같은 fontSize 에서도 glyph advance/kerning/line-height 가 다름 → bounds 와 render 크기 mismatch

### 왜 Phase 2 범위 밖인가

Phase 2 handoff 원칙 5:
> 5. 코드는 결과를 추출한다.

Toolditor FE 에서 `"sans-serif" → "701_400"` 하드코딩 매핑은 **추출 결과를 재해석하는** 위반이 된다. 문제의 원천은 extraction 이 올바른 폰트를 쓰지 않은 것. 고쳐야 할 위치는 **extraction pipeline** 이다.

## 철학 (Phase 2.5 내부 재선언, Phase 2 와 동일)

- **시스템이 layout family 를 정의하지 않는다.**
- **Slot / topology / CTA / role 같은 개념을 contract 로 올리지 않는다.**
- **LLM 은 결과를 만든다.**
- **브라우저는 layout 을 계산한다.**
- **코드는 결과를 추출한다.**

Phase 2.5 목적은 원칙 4 의 "브라우저" 가 Playwright extraction ↔ Toolditor render 양쪽에서 **동일한 font asset set 을 쓰도록** 환경을 정렬하는 것. 새 layout 정책을 만들지 않는다.

## 목표

v6 pipeline 의 font-handling 3 단계를 단일 SSOT 기준으로 정렬:

1. **Playwright extraction** — Toolditor 가 실제로 쓰는 webfont 를 `@font-face` 로 로드 후 측정
2. **LLM prompt** — 로드된 CSS font-family 이름만 사용하도록 명시
3. **v6CommandAdapter** — 추출된 `(cssFontFamily, fontWeight)` 를 Toolditor font ID (`701_400` 등) 로 매핑

결과: Toolditor FE 는 이미 `fontFamily` 로 전달된 ID 를 그대로 렌더 (현재 Phase 2 구현) → visual 일치.

### 대안 비교

| 옵션 | 방법 | 장점 | 단점 | 선택 |
|---|---|---|---|---|
| A. Full registry mirror | Toolditor backend `loadFontData()` 를 Playwright 에서 fetch 후 전체 font 를 `@font-face` inject | 자동 sync | 100s 폰트 → 느린 warm-up, 네트워크/인증 복잡도, 불필요한 다양성 | ❌ |
| **B. Curated subset + static SSOT** | `agent-workflow-test/fonts/registry.json` 에 소수 (4-6개) 폰트 고정 → Playwright + adapter + prompt 모두 이 JSON 을 참조 | MVP 빠름, 결정적, 디버깅 쉬움, 필요 시 append-only 로 확장 | 수동 sync | ✅ |
| C. FE 쪽 매핑 | Toolditor FE 에서 "sans-serif" → "701_400" | 간단 | 원칙 5 위반, metric mismatch 여전 | ❌ |
| D. FE 쪽 재측정 | FE 에서 text bounds 를 재계산 | 폰트 독립적 | 원칙 4 위반 (브라우저 대신 FE 가 측정), 여백/정렬 깨짐 | ❌ |

**B 선택**. 이유:
- PoC + bench 범위가 폰트 다양성보다 정확성 우선
- MVP 빠르고, Phase 4 전 prerequisite 만족에 최적
- 추후 Phase 4 이후 (or 이전) 에 A 로 swap 하기 쉬운 구조

```jsonc
    { "cssName": "Roboto",     "weight": 400, "style": "normal", "toolditorId": "702_400", "url": "...", "format": "woff2", "language": "ENG" },
    { "cssName": "Roboto",     "weight": 700, "style": "normal", "toolditorId": "702_700", "url": "...", "format": "woff2", "language": "ENG" }
  ],
  "default": { "cssName": "Pretendard", "weight": 400 }
}
```

**실제 폰트 선정 방법**:
1. Toolditor backend `GET /editor/loadFont` 호출 (개발 계정)
2. 응답에서 `fontLanguage === 'KOR'` 이면서 `fontWeights` 가 여러개인 폰트 2-3개 pick (Korean primary)
3. `fontLanguage === 'ENG'` 에서 1-2개 pick (English secondary)
4. 각 폰트의 `savedFilename` → Toolditor CDN URL 조합 규칙 확인 (`loadFontData` 응답이나 Toolditor 의 font CSS 생성 로직 `src/util/font/getFontSrc.ts` 참조)

## 구현 단계 (순서 의존적)

### 1. registry.json 초안 + 폰트 URL 검증

- Toolditor dev 계정으로 `/editor/loadFont` 호출 → 폰트 목록 dump
- 4-6개 선정 후 `agent-workflow-test/fonts/registry.json` 작성
- 각 URL 을 Playwright 기동 환경에서 `fetch()` 테스트 → 200 응답 확인
- 200 실패 시 (CORS / 인증 필요) → woff2 파일을 `fonts/assets/` 에 내려받고 registry.url 을 로컬 경로로 바꾼다. Playwright 는 `page.route` 로 로컬 서빙

### 2. FontFace CSS generator 유틸

`agent-workflow-test/v6-poc/fonts/buildFontFaceCSS.mjs` (PoC용) + `tooldi-agent-runtime/apps/agent-worker/src/phases/v6FontRegistry.ts` (prod용) 에 동일 로직:

```js
export function buildFontFaceCSS(registry) {
  return registry.fonts.map(f =>
    `@font-face {
      font-family: "${f.cssName}";
      src: url("${f.url}") format("${f.format}");
      font-weight: ${f.weight};
      font-style: ${f.style};
      font-display: block;
    }`
  ).join('\n');
}
```

**DRY 유지**: `v6FontRegistry.ts` 가 `agent-workflow-test/fonts/registry.json` 을 `readFileSync + JSON.parse` 로 직접 import. v6-poc 도 같은 파일을 relative 로 읽음. 중복 없음.

### 3. Playwright HTML template 수정

**두 경로 모두 수정**:
- `v6-poc/extract.mjs` — PoC sample 렌더 시 HTML `<head>` 맨 위에 `<style>@font-face...</style>` inject
- `tooldi-agent-runtime/apps/agent-worker/src/phases/v6BrowserRender.ts` — prod LLM HTML 을 Playwright 에 load 하기 전에 동일하게 inject

**주의**: `document.fonts.ready` await 는 이미 있음. 추가 조치 불필요.

### 4. PoC samples 재작성

`v6-poc/samples/*.html` 에서 `font-family: sans-serif` → `font-family: "Pretendard"` (또는 registry 에서 선택한 CSS 이름). Phase 0 의 5개 샘플 전부.

### 5. v6SystemPrompt 업데이트

`tooldi-agent-runtime/apps/agent-worker/src/phases/v6SystemPrompt.ts` 에 **"사용 가능한 font-family CSS 이름 목록"** 을 명시. 예:

```
Available fonts (use via font-family CSS property):
- "Pretendard" — weight 400, 700, 900 (Korean + English)
- "Roboto" — weight 400, 700 (English only)

Do NOT use generic CSS names like "sans-serif", "serif", or OS-specific names.
```

### 6. v6CommandAdapter 의 text 매핑

`apps/agent-worker/src/phases/v6CommandAdapter.ts` 의 `textTokens(cmd)` 에서:

```ts
function textTokens(cmd: V6TextCommand): Record<string, unknown> {
  const resolved = resolveToolditorFontId(cmd.fontFamily, cmd.fontWeight);
  return {
    fillColor: cmd.color,
    fontFamily: resolved.toolditorId,  // ★ CSS name 대신 Toolditor ID emit
    fontSize: cmd.fontSize,
    fontWeight: resolved.weight,        // numeric, normalized
    ...
  };
}
```

`resolveToolditorFontId` 는 registry 에서 `(cssName, weight)` → `{ toolditorId, weight }` 검색. 미매칭 시 **dev: throw**, **prod: default + warning log**.

**주의**: `cmd.fontFamily` 는 `computedStyle.fontFamily` = `"Pretendard", sans-serif` 형태의 CSS cascade 문자열. 첫 이름만 파싱해서 registry 조회. "sans-serif" fallback 은 경고 없이 무시.

### 7. v6PrimitiveMapper 의 weight 처리

Playwright `getComputedStyle().fontWeight` 는 `"400"` string. 이미 `V6TextCommand.fontWeight` 가 string 이지만, registry 조회 시 number 로 normalize. 100 단위 반올림 (e.g., 450 → 400).

### 8. Fixture generator 재실행

- `v6-poc/extract.mjs` 재실행 → 새 bounds (webfont 기반) 추출
- `v6-poc/run.mjs` 로 adapter 통과 → commands 재생성
- `node v6-poc/buildToolditorFixtures.mjs` → Toolditor fixtures 재생성
- Toolditor fixture 주입 → **text 가 Toolditor 등록 폰트로 깨끗이 렌더됨을 시각 확인**

### 9. 기존 Phase 2 test 업데이트

Phase 2 의 `mutationAdapter.test.ts` 에 있는 v6 text 테스트는 `fontFamily: "sans-serif"` 로 expect 하는 부분 있음. `"701_400"` 같은 Toolditor ID 로 변경. adapter 단계 test 이지 builder 단계 test 가 아니므로 영향 범위 작음.

## Out of Scope (의도적)

- **Toolditor 의 전체 font registry (100s 개) 커버**: Phase 2.5 는 4-6개 curated subset. 확장은 후속.
- **Italic / oblique / variable fonts**: `font-style: normal` 만 지원.
- **Dynamic font list** (`loadFontData()` 를 Playwright warm-up 에서 live fetch): 후속 phase. 지금은 static JSON SSOT.
- **Unicode-range subsetting** (성능 최적화): 후속.
- **Font licensing validation**: 이미 Toolditor 가 라이선스 보유한 폰트만 등록하는 전제.
- **Toolditor FE font ID 리네이밍**: `701_400` 같은 기존 ID 를 그대로 사용.
- **Phase 4 LangGraph swap 범위 침범**: 오직 Playwright extraction + adapter + system prompt 만. LangGraph node 교체는 Phase 4.

## 리스크

| # | 리스크 | 영향 | 대응 |
|---|---|---|---|
| R-1 | Toolditor font CDN 이 공개 아님 (auth required) | Playwright fetch 실패 | woff2 파일을 repo 내 `fonts/assets/` 에 내려받고 `page.route` 로 로컬 서빙. 점검 1순위. |
| R-2 | Font cold-start latency (woff2 다운로드 수십 KB × 4-6개) | Playwright 첫 render ~200-500ms 추가 | 로컬 cache + `font-display: block` 으로 FOUT 방지. 수용 가능. |
| R-3 | CSS `font-family` cascade ("Pretendard", sans-serif) 파싱 에러 | Adapter 에서 잘못된 ID 매핑 | `.split(',')[0].replace(/['"]/g, '').trim()` 으로 robust 파싱. registry 미매칭 시 dev throw / prod default. |
| R-4 | OS 간 Chromium font rendering 차이 (subpixel / hinting) | 1-2px 오차 | 수용. Phase 2.5 acceptance 는 "시각 일치" 수준이지 pixel-perfect 아님. |
| R-5 | LLM 이 prompt 지시를 무시하고 "sans-serif" 등 사용 | Adapter reject → 전체 run 실패 | System prompt 강한 constraint + adapter 에 1회 warning 후 default fallback 전략 고려 (dev 는 strict, prod 는 lenient). |
| R-6 | Phase 4 LangGraph swap 시 registry 경로 변경 필요 | 후속 작업 충돌 | registry 경로를 env var (`V6_FONT_REGISTRY_PATH`) 로 추상화해 Phase 4 에서 이동 가능하게. |

## Anti-pattern (즉시 제동)

- [ ] Toolditor FE 에서 `"sans-serif" → "701_400"` 하드코딩 매핑 추가 — **금지**. Extraction 쪽에서 원천 해결.
- [ ] Adapter 가 unknown font-family 를 임의로 Toolditor ID 에 mapping — 금지. Reject or default, silently 매핑 금지.
- [ ] `font-family` 에 LLM 이 임의의 CSS 이름을 쓸 수 있도록 허용 — 금지. System prompt 에서 명시된 list 만.
- [ ] Registry 를 여러 곳에 중복 (v6-poc 와 agent-worker 각자) — 금지. Single JSON 파일 공유.
- [ ] Italic / weight 450 같은 비등록 style 을 자동 합성 — 금지. 최근접 등록 weight 로 매핑 (100 단위 반올림).
- [ ] Toolditor 측 변경 (font store, loader, FE materialization) — 금지. Phase 2.5 범위 밖.
